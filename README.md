# PCD —— Phigros 谱面下载与工具集

PCD 是一个 Phigros 谱面下载站，附带答题验证、导航中心、网盘索引与谱面工坊等入口。
谱面、曲绘、音频统一从上游公开仓库拉取，本地只做索引、筛选与打包。

- 在线地址：https://pcd.bot.cd/
- 技术栈：Vite + React + TypeScript（下载器）、原生 HTML/JS（答题页与各入口页）

## 页面说明

| 页面 | 作用 |
|---|---|
| `quiz.html` | 从加密题库随机抽 5 题，全部答对后签发凭证，跳转目标页 |
| `home.html` | 导航中心，展示各工具入口 |
| `philzy.html` | 蓝奏云网盘索引 |
| `pmth.html` | Phigros Chart Studio 谱面工坊：导入谱面，应用规则后导出 |
| `/`（下载器） | 谱面下载主站 |

谱面工坊处理用户上传的谱面文件（`.json` / `.zip` / `.pez`），
应用替换规则与特性后导出。**输出格式跟随输入**：导入 `.pez` 就导出 `.pez`
（`.pez` 本质是改了扩展名的 zip，Phira 靠扩展名识别，写成 `.zip` 就认不出来了）。

> 谱面工坊导出的是谱面 JSON，需要放进 Phira 能识别的容器里。`.pez` 就是
> 那个容器 —— 本质是把 `info.txt` + 谱面 JSON + 曲绘 + 音频打包后改了扩展名
> 的 zip。Phira 靠扩展名判断能不能导入，所以扩展名写错会直接导致导入失败。

> 导入时的格式会一路记在每张谱面上（`ext` 字段），导出时按它还原，
> 不会因为文件名里没有扩展名就掉回 `.json`。

**支持压缩包套压缩包**：上传下载站导出的那种「按歌曲分目录、每难度一个
`.pez`」的压缩包时，会自动递归展开成多张谱面，并按歌曲名与难度编号：

```
上传 songs.zip
  → DESTRUCTION_3,2,1/  ×  EZ / HD / IN / AT
  → Glaciaxion/         ×  EZ / HD / IN
  → 展开为 7 张，按「歌曲名 · 难度」逐条列出
```

也兼容「原始资源平铺」格式（`曲名/charts/*.json`），以及两者混合的目录。
曲名与难度优先从包内 `info.txt` 的 `Name` / `Level` 行读取，读不到才按文件名猜。

批量上传多张谱面时，可勾选「分别处理所有勾选谱面，打包成一个压缩包」，
得到内含各难度独立谱面包、且按歌曲分目录的压缩包；
不勾选则只处理主谱面，或走「整合」混排成一张。

**噪域（blockArea）**

Phigros 新版在谱面里新增了 `blockAreaList`（噪域）：按两个对角坐标定义矩形区域，
在 `enableTime ~ disableTime` 期间遮挡屏幕；`isSubtract` 为真是「减算」，即挖洞。

工坊在「整合」面板提供噪域下拉，四种处理方式：

| 选项 | 行为 |
|---|---|
| 保留原样 | 不动，整合时随主谱面带过去 |
| 合并并去重 | 所有谱面的噪域合进来，按「坐标 + 四时间点 + isSubtract」去重 |
| 只保留主谱面 | 其他难度的噪域丢弃 |
| 删除所有噪域 | 输出干净谱面 |

谱面列表会显示每张的噪域数量，下拉下方显示构成（遮挡 / 挖洞各多少）与覆盖时间跨度。

「谱面统计」卡片底部还有一块噪域概览：总数、遮挡/挖洞的构成条、
以及覆盖的时间跨度（m:ss）。没有噪域时显示「当前谱面没有噪域」。

**界面控件的一致性**

工坊里的下拉与复选框都是自绘的，不用浏览器原生控件 —— 原生 select 在手机端会
弹出系统控件、桌面端各浏览器渲染也不一致，深色界面里很跳；原生 checkbox 是白底
方块，同样违和。

自绘下拉保留原生 `select` 作为数据源（加 `.cmb-src` 隐藏），只替换外观 ——
读 `.value`、监听 `change` 的既有代码都不用改。禁用项（`option.disabled`，
规则行靠它避免 `from == to` 的无意义映射）在自绘下拉里同样不可点。

面板里的行、提示、输入框统一用 `.mo-row` / `.mo-tip` / `.mo-field`，
色值全部走 CSS 变量。这些样式原先挂在 `.merge-opts` 前缀下，
导致批量面板用同样的类名却拿不到样式、只能靠内联 style 硬凑另一套颜色。

> 噪域需要 `formatVersion >= 3`。若主谱面是老版本而整合时合并进了噪域，
> 工坊会自动把版本升到 3 —— 否则版本号还是旧值，Phira 认不出 `blockAreaList`。
>
> ⚠️ 官方文档把动画字段写成 `rotateEventsList` / `moveEventsList` / `scaleEventsList`，
> 但实谱里**没有 `List` 后缀**（是 `rotateEvents` / `moveEvents` / `scaleEvents`）。
> 照文档写会取到 `undefined`。目前只做搬运/去重/删除不读事件，
> 将来若要编辑噪域动画，务必用无后缀的名字。

**info.txt 与 info.yml 会一起改**

两个文件作用相同（yml 是下载站额外附带的等价描述文件），
所以难度标识会同步写入两者，不会只改一个导致包内信息自相矛盾。
查找文件名大小写不敏感，子目录内的也能找到。

**输出命名：歌曲名 + 难度标识**

```
Exoplanetary Mirage_AT.pez
```

标识规则：

| 标识 | 含义 |
|---|---|
| `ALL TAP` | 全部转为 Tap |
| `ALL DRAG` | 全部转为 Drag |
| `ALL HOLD` | 全部转为 Hold |
| `ALL FLICK` | 全部转为 Flick |
| `RANDOM` | 随机 |
| `MIXTURE` | 整合混排 |
| `AX` | 自定义类型映射 |
| `IN` 等 | 未做转换时，保留谱面原本的难度 |

文件名与包内 `info.txt` / `info.yml` 的 `Level` 字段用同一套标识，
全部大写。整合统一记 `MIXTURE`，不再把参与难度拼进去（如 `MIX-EZHDINAT`）。

标识含空格（如 `ALL TAP`），所以替换时按「`Lv.` 及之后」切分、
只改它前面的部分 —— 对已处理过的文件再跑一次不会叠成 `ALL ALL TAP`。

答题页的几个机制：

- **随机抽题**：每轮从题库随机抽 5 题并打乱选项顺序
- **会话倒计时**：5 分钟未提交会自动换一批题
- **连续答错冻结**：连续答错 5 次会冻结 10 分钟，可等待或用管理员密码解锁
- **自助脱困**：冻结页与错误页提供清除本页本地状态并重新加载的入口

## Token 鉴权机制

所有页面共用同一套凭证：

1. **答题页**：答对后生成 `access_token` 存入 localStorage，格式为 `base64("时间戳|随机uid|djb2签名")`，**有效期 12 小时**。
2. **导航中心 / 网盘 / 工坊**：加载时校验凭证，无效则显示「访问受限」弹窗，可返回答题页。
3. **下载器**：由 `AuthGate` 组件校验，无效时显示全屏受限页。

### 验证后返回原页面

被拦截时，页面把当前地址通过 `?return_to=` 传给答题页，答完自动跳回，
而不是一律落到导航中心。典型场景：

```
扫码打开 /?song=xxx → 凭证失效被拦
  → quiz.html?return_to=...%3Fsong%3Dxxx
  → 答对 → 回到 /?song=xxx（自动选中那首歌）
```

**例外**：下载站只在带 `?song=` 的分享链接时才原路返回。直接访问下载站
首页被拦时，答完题会去导航中心 —— 从那里能进下载器，不会停在空白曲库上。
其他受保护页面无论有没有参数都照常回跳。

安全与可靠性上的几条约束：

- **只看当前链接的 `?return_to=`，不读写任何本地存储**。地址栏里没有就当作没有，不会出现残留的跳转目标。
- **白名单校验**：只接受同源且属于白名单页面（`index.html` / `home.html` / `philzy.html` / `pmth.html`）的返回地址，答题页自身排除在外，避免「弹回 → 答完 → 再弹回」死循环。
- 新增受保护页面时，需同步答题页里的 `ALLOWED_PATHS`。

## 谱面下载器

### 选歌与筛选

选歌按钮右侧的漏斗图标可按 **难度 / 谱师 / 曲师** 筛选曲库：

- **必须含难度**：EZ / HD / IN / AT 可多选，需同时满足
- **指定定数**：精确的定数，可带小数也可不带（`17`、`17.6`、`15.3` 都行）；
  多个用逗号分隔（`15.3, 17.6`），之间是「或」的关系
- **定数区间**：任一难度落在区间内即命中
- **谱师 / 曲师**：可输入也可选择，输入实时过滤候选，聚焦或点箭头展开列表

> 「指定定数」与「定数区间」可同时填写，此时需要两者都满足（是「且」不是「或」）。
> 填了互相矛盾的条件会得到空结果 —— 这是预期行为，不是 bug。
>
> 定数比较带 0.05 的容差：上游同一数值可能写成 `17.6` 或 `17.60`，
> 直接用 `===` 比较浮点会因精度问题漏掉。0.05 远小于定数最小间隔 0.1，不会误判。

按钮上有角标显示生效了几项筛选；下拉顶部显示当前筛选条件，可一键清除。
筛选与关键词搜索是叠加关系（先在筛选结果里搜）。

几个实现上的取舍：

> 谱师/曲师用自绘组合框而非原生 `<select>` —— 浏览器自己画的下拉面板
> 和站点深色风格对不上。设置里的「导出图片类型」同理改成了分段控件。

> 输入时做「包含」匹配方便找人，真正生效的筛选仍用**完全匹配**，
> 保证选中的谱师精确对应一个人。打了一半就失焦会回退到上一个有效值，
> 不会留下「筛不出东西但看不出原因」的状态。

> 作品数按「歌曲」计而非「难度条目」计 —— 同一首歌多个难度都是同一位谱师
> 时只算一首，避免下拉显示 37 却只筛出 24 首。

### 难度与导出

导出格式可在设置里选 `.pez`（Phira 原生）或 `.zip`，
可选附带 `info.yml`。

**未指定难度时导出该曲全部难度**：每个难度一个包，再统一打包成一个
压缩包，文件名形如 `曲名_all-difficulties.zip`，解压后逐个导入即可。
指定了难度才只导那一个。

曲目实际拥有的难度以难度表为准 —— 缺列、空串、`—`、`?`、`∅`、`0`
都视为「不存在」。全库 320 首中 271 首没有 AT，这些曲子不会凭空多出 AT 行。

### 批量下载

在设置里开启「批量下载模式」后，主界面换成批量面板：先筛选，再勾选，最后打包。

**筛选条件**

| 分类 | 条件 |
|---|---|
| 基础 | 关键词（曲名 / ID / 作曲家 / 谱师）、作曲家包含、谱师包含 |
| 定数 | 精确值（逗号分隔）+ 区间筛选，可作用于「任一难度 / 最高难度 / 指定难度」 |
| 难度 | 必须含哪些难度（可多选） |
| 安全 | 排除含黑名单谱面的曲目（默认开启） |
| 谱面数据 | BPM、时长、物量、判定线（需解析谱面，勾选后才启用） |

**导出难度**

默认导出每首歌的**全部难度**。只想练某个难度时可单独指定，
歌曲没有的难度自动跳过；若指定的难度该曲一个都没有，退回它实际拥有的
（不会导出空包）。列表每行显示该曲拥有的全部难度徽章，一眼看清会下几个。

**打包方式**

默认「每难度独立谱面包」，产出的结构是：

```
曲名/
├── 曲名_EZ.pez
├── 曲名_HD.pez
├── 曲名_IN.pez
└── 曲名_AT.pez
```

每个难度一个可直接导入 Phira 的谱面包，解压后逐个导入即可。
代价是同一份曲绘/音频会在每个难度的包里各存一份，体积较大。

想省体积可切到「原始资源平铺」：曲绘与音频各存一份，
谱面 JSON 放在 `charts/` 目录，但需自行组装才能导入。

两种模式下资源都**每首歌只下载一次**再复用给所有难度，
请求数不会因为打包方式而增加。若某首歌的曲绘或音频下载失败，
该曲会退化为只放谱面 JSON，不至于整首消失。

**其他**

- 曲目列表可逐条勾选或「全选筛选结果」；被筛掉的曲目自动移出选中集合
- 支持分批打包（默认每包 50 首），避免单个巨型压缩包
- 开始前显示摘要：多少首、几个包、约多少次请求、预计耗时（默认间隔 0.6 秒）
- 含黑名单谱面时开始前统一提示确认，而不是逐首弹窗
- 结束后列出失败文件，可「仅重试失败的曲目」

**请求量与限流**

每首歌的请求数 = 非谱面资源（每难度独立包模式为 1 张曲绘 + 音频，
平铺模式为 3 张曲绘 + 音频）+ 实际难度数。
因为不再盲目试 4 个难度，全库谱面请求从 1280 次降到 1009 次。

GitHub 有非官方限流（约 5000 次/小时），建议保留 0.5 秒以上的歌曲间延迟。

### 分享卡片

选中曲目后可生成 1080×1440 的分享图，内容包含曲绘、曲名、曲师、
各难度定数与谱师、二维码等。**17 套配色**：

暗夜、极光、暖阳、青林、樱雪、深海、曜金、熔岩、冰川、石墨、
霓虹、薄荷、星海、摩卡、青柠、珊瑚、素白

其中「素白」为浅色主题，卡片会自动切换深色描边与文字，无需额外适配。

卡片上的可选项（BPM / 判定线 / 时长 / 各难度物量）在设置里独立开关，
全部关闭时无需解析谱面，打开即出图。

### 设置项

| 分类 | 项目 |
|---|---|
| 导出 | 导出格式（`.pez` / `.zip`）、附带 `info.yml`、导出图片类型（原始 / 模糊） |
| 界面 | 使用新界面（音频预览、音量、循环、可视化、曲目特效） |
| 批量 | 批量下载模式 |
| 分享卡片 | 总开关 + BPM / 判定线 / 时长 / 物量 |
| 其他 | 禁用匿名统计 |

带子项的设置（批量下载、分享卡片）在总开关关闭时会自动收起子项，
打开时默认展开，也可手动折叠。

### 加速源

可在界面切换 5 个源：GitHub 直连、jsDelivr CDN、gcore CDN、
ghproxy.net、gh-proxy.com。国内推荐 jsDelivr 或 gcore。

索引类数据（版本 / 曲目表 / 难度表）会带 CDN 版本号参数，
点「清除缓存」时递增版本号以强制 CDN 回源 —— 否则上游更新了，
CDN 边缘节点仍会返回旧内容。

「清除缓存」会注销 Service Worker、清空 Cache Storage / IndexedDB /
sessionStorage，但**保留**登录凭证、已选加速源与 CDN 版本号，
避免清完掉回 GitHub 直连或需要重新答题。

### 黑名单

`blacklist.ts` 记录已知会导致 Phira 卡死的谱面（按曲目 + 难度）。
下载前会提示确认，批量下载时统一提示一次。

## 本地开发

### 完整打包预览（推荐，贴近线上）

```bash
cd Download
npm install
npm run build     # 输出到 Download/dist
cd dist
npx serve .
```

然后把根目录的 `*.html` 与 `*.data` 复制到 `Download/dist/` 下
（部署流程里由 CI 完成这步），即可访问：

| 页面 | 地址 |
|---|---|
| 答题页 | `/quiz.html` |
| 导航中心 | `/home.html` |
| 蓝奏云 | `/philzy.html` |
| 谱面工坊 | `/pmth.html` |
| 谱面下载器 | `/` |

### 开发模式（仅调试下载器）

```bash
cd Download
npm install
npm run dev       # 端口 3000
```

开发模式下只有下载器页面；其余 HTML 页面需放到 `Download/public/` 才能访问。

## 部署

推送到 `main` 分支后，`.github/workflows/deploy.yml` 自动执行：

1. 安装依赖并构建下载器（输出到 `Download/dist`）
2. 把根目录的 `*.html`、`*.data`、`CNAME` 复制进 `Download/dist`
3. 以 `Download/dist` 为发布目录部署到 GitHub Pages

首次部署需要在仓库 Settings → Pages → Source 选择 `GitHub Actions`；
换域名时改 `CNAME` 文件内容即可。

## 注意事项

1. **所有页面必须通过 HTTP 服务器访问**，不能直接双击打开 ——
   `file://` 协议会禁用 Web Crypto API，导致题库解密和凭证鉴权失效。

2. **`.data` 文件需自备**：`pcd.data`、`dl.data`、`lz.data` 是加密的
   题库与站点数据文件，不包含在仓库中。

3. **凭证仅存本地**：凭证保存在浏览器 localStorage，换浏览器、换设备或
   清理站点数据后需要重新答题。

4. **上游限流**：批量下载大量曲目时请保留歌曲间延迟，避免触发限流
   导致整批失败。

5. **谱面版权**：谱面与曲绘版权归各自作者与 Phigros 官方所有，
   本项目仅做索引与下载，请勿用于商业用途。

6. **密钥类信息不要硬编码进仓库**：管理员密码、题库解密口令、统计用的
   Webhook 地址等敏感值不应提交到公开仓库。如需更换，请同步修改
   对应页面与源码中的引用处，并把旧值作废。
